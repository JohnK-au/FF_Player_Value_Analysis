TabFM Research · Architecture & Findings

Predicting next season from what we knew at the end of this one.

How the standalone TabFM analysis is built — six stages from raw box scores to an honest, leak-free forecast — and what it found: a 13 GB foundation model that ties a plain linear regression.

01 · THE ONE IDEA

Two seasons, side by side

Every row in this project is a single player at one transition: everything we knew about them at the end of season t, paired with what they actually did in season t+1. The model reads the left half and predicts the right half. Nothing from the future is ever allowed to leak into the features — that single rule shapes the entire pipeline.

The colour code runs through this whole page: amber is the known present (features, the model), slate is the future (the target we're trying to hit).

05 · WHY TWO ENVIRONMENTS

A Parquet file is the border crossing

TabFM needs Python 3.11. The project's data code needs Python 3.9 (an old pandas the nflverse library pins). Those can't coexist — so the pipeline is deliberately split across two isolated environments, and a single Parquet file is the contract between them.

Real gotcha, already hit Parquet needs an engine on both sides of the border. The project venv had pyarrow; the TabFM venv didn't, so its first read failed until it was installed there too. The handoff format is only free if both ends can speak it.

06 · THE HONEST TEST

Rolling-origin backtests

07 · THE MODEL CONTRACT

One socket, five plugs

Every model — the four baselines and TabFM — is just a function with the same shape. That uniformity is why baselines come first: the harness gets debugged on cheap, instant models, and TabFM later drops into the identical socket with no special-casing.

model(train_df, test_df) → predictions
persistence
returns each player's own season-t PPG. The bar to beat.
position_mean
shrinks toward the positional average — regression to the mean.
ridge
linear yardstick. Impute → scale → linear fit.
histgbr
gradient-boosted trees. NaN-native classical-ML yardstick.
tabfm
the foundation model — Phase 3, same signature.
The ablation, built into the socket feature_matrix() can switch whole feature bundles on or off — core / consistency / advanced. Running each model with and without a bundle measures what that bundle is worth, instead of assuming. That's how the advanced stats earn (or lose) their place in Phase 3.

08 · WHAT RESULTS LOOK LIKE

The scoreboard

Stage 6 prints one row per model per backtest. Four numbers, because no single one is enough: MAE (points off), R² (variance explained), Spearman (did we rank players right — what your league decisions actually need), and calibration slope (are elite predictions compressed toward the mean?).

Real numbers, backtest A (predict 2024, 283 players). Ridge wins; its edge over persistence is bootstrap-confirmed real — MAE-delta 95% CI [−0.86, −0.17], entirely below zero. Backtest B (predict 2025) is stronger still: Ridge MAE 3.11, R² 0.54.

Two things stand out. Everything beats persistence, and the gap is real — but nobody is great: best MAE is ~3–4 PPG, best R² ~0.5. Half of next season is genuinely unpredictable from prior stats, and that's the honest ceiling.

The calibration slopes bracket the sweet spot: persistence 0.64 (too extreme — it ignores that elite seasons regress), position_mean 1.18 (too timid — it over-shrinks to the average), Ridge 0.98 (just right). The right amount of regression to the mean, learned.

And the model to beat is a plain linear regression — which hints the signal here is largely linear, setting a genuinely high bar for whether TabFM's 13 GB earns its keep in Phase 3.

09 · THE VERDICT

Does the foundation model beat the bar?

The bar was Ridge (§8). Here's what a 13 GB, in-context foundation model does against it on next-season PPG — the question the whole project was built to answer.

vs the easy bar · persistence
−0.9 PPG
TabFM clears "next year = this year" comfortably (MAE 3.10 vs 4.00 in 2025). It learned real signal.
vs the real bar · ridge
a tie
MAE 3.10 vs 3.11. The paired-bootstrap 95% CI straddles zero in both backtests — no clear winner. Statistically indistinguishable from linear regression.

Everything else we tried to give TabFM an edge came up empty — measured, not assumed:

tier ablation

Extra features add nothing

Dropping the advanced or consistency tier moves MAE by ±0.01–0.06, sign flipping across years. Core stats (prior PPG + box score) carry the signal.

stratified

No hidden subgroup

Sliced 12 ways by position × scoring tier, consistency helps in no cell that holds across both backtests. Big deltas live only in tiny, noisy cells.

residualized

Not a confounding artifact

Deconfounding consistency from PPG doesn't rescue it. On Ridge it's a dead wash — the linear model already deconfounds itself. No signal, three ways.

two experts

Agree 0.81, split on age

TabFM and the V2 engine rank-agree strongly. Where they diverge it's clean: TabFM rates aging vets high (next-year points), V2 rates young WRs high (dynasty horizon).

Honest caveat — the "which is right" tiebreaker V2's dynasty_value ranks actual-2025 better than TabFM (0.84 vs 0.76) — but V2 was built from data through 2025, so it partly describes the season rather than forecasting it. TabFM's number is clean out-of-sample. Not a fair fight; flagged, not spun.

10 · WHAT IT MEANS

Reach for the linear model

For this task — forecasting next-season fantasy PPG — a plain Ridge regression is the right tool, and TabFM's 13 GB earns nothing extra. The reason is baked into the data: next-season signal is largely linear and lives mostly in a player's prior PPG. A foundation model's edge is flexibility — nonlinear interactions, in-context patterns — and there's little of that here for it to exploit.

That's not a knock on TabFM; it's a finding about the problem. Fantasy production a year out is genuinely noisy (best R² ~0.5 — half is unpredictable), and what structure exists is simple. The model did its job; the job just didn't need it.

The result worth keeping isn't only the verdict — it's that the machinery could tell the difference. Baselines published before the headline model, bootstrap CIs instead of point estimates, ablations that measure rather than assume, and a leak-free backtest throughout. Without that scaffolding, "TabFM beats persistence by 0.9 PPG!" reads as a win. With it, the honest story is visible: a tie, and a problem that a linear model already solves.

The one-line takeaway A foundation model is only worth its cost when the problem has structure a simpler model can't reach. Always make it prove that against an honest bar — here, it couldn't, and knowing so is the win.
